## Data layer (no ORM)

This project does **not** use an ORM (no Core Data, SwiftData, GRDB, or Realm for server data).

| Layer | What it is |
|-------|------------|
| **Supabase Swift SDK** | HTTP client for Postgres (PostgREST), Auth, Storage, Functions |
| **Codable structs** | `UserProfile`, `DBConversation`, `DBCircle`, etc. — hand-written row types |
| **Repositories** | `ProfileRepository`, `DevotionSessionRepository`, `CircleRepository`, `ConversationRepository` |
| **SQL migrations** | Schema lives in `supabase/migrations/*.sql` (source of truth for Postgres) |
| **Local state** | `UserDefaults` via `StreakManager`, `JourneyTimelineStore`, offline queues |

That is the usual Supabase + mobile pattern: **migrations define the DB**, **repositories + Codable** replace an ORM. Adding an ORM would not replace migrations or edge functions; it would mostly duplicate what the SDK already does.

Optional later: `npx supabase gen types typescript --linked` for edge functions (TypeScript only). Swift types stay manual or generated by a custom script.

## Apply migrations & deploy functions

### Option A — CLI (recommended once set up)

One-time login and link:

```bash
cd devotionlock-mobile
npx supabase login
npx supabase link --project-ref ygirplpbgxwvstnqxnrz
```

Deploy migrations + all edge functions:

```bash
./scripts/deploy-supabase.sh
```

Migration files **must** be named `YYYYMMDDHHMMSS_description.sql`. If `db push` says remote migrations are missing locally, run:

```bash
npx supabase migration fetch   # download remote history into supabase/migrations/
npx supabase db push           # apply any new local migrations
```

Or individually:

```bash
npx supabase db push
npx supabase functions deploy delete-account --no-verify-jwt
```

### Option B — SQL Editor (no CLI)

See **`scripts/apply-migrations-sql-editor.md`**.

1. SQL Editor → paste **`supabase/migrations/20260607040000_profiles_account_management.sql`** → Run  
2. Edge Functions → deploy **`delete-account`** from `supabase/functions/delete-account/index.ts`

Do **not** paste `supabase db push` into SQL Editor — that is a terminal command, not SQL.

## Schema

Applied via migrations:
- `initial_schema` — profiles, devotion_sessions, conversations, messages, journey_entries, ai_insights, devotion_completions
- `prayer_circles_phase2` — prayer_circles, circle_memberships, circle_posts, circle_encouragements + RLS + Realtime

## iOS sync architecture

- **Local-first:** StreakManager, PrayerCircleStore, PrayerWallStore stay in UserDefaults.
- **Offline queue:** `DevotionOfflineQueue` + `CircleOfflineQueue` persist pending writes; `SyncCoordinator` flushes on launch, foreground, and sign-in.
- **Widgets:** `SharedDataSync` → App Group snapshot (unchanged; circles are not in widget data).
